# I4-A-02. Независимые проверки интеграции

Контрольный набор подготовлен и запущен против существующего эталонного решения. Код новой реализации Кирилла ещё не подключён: её интеграционная проверка не заявляется.

| Случай | Ожидание |
|---|---|
| Полный H/L/L в base | Допустим, цель 2.50, расходы 1.0/0.9/1.1 т |
| deficit | Перебор не находит полного допустимого назначения, MILP возвращает infeasible |
| Запрет H первому заказу; проверяется старый H/L/L | invalid_plan: запрещённый кандидат; не вывод о невозможности всей задачи |
| changed_q | Оптимум 2.35; старый H/L/L оценивается в 1.65 |
| Пустой результат без доказательства | no_solution_found, а не infeasible |
| Неверная структура выхода | error; не считать infeasible |

Применяются отдельные T06: `../validate_plan.py` и `../score_plan.py`; q передаётся явно. Сравнение с независимым перебором и эталонным MILP — `../reference_case.py`. Единицы: т и условный балл·т; ресурсный допуск 1e-8+1e-9*abs(stock), цель abs_tol=1e-8, rel_tol=1e-9.

Запуск из корня: `python alexey/iteration4/check_controls.py`. Нужны numpy и scipy. Результат: `control_results.json`, включая версии, hash входов и число проверок. Для будущего модуля Кирилла сохраняются тот же набор и независимый валидатор, но требуется адаптер фактического контракта K01. Успех контрольной программы не заменяет проверку этого модуля.
