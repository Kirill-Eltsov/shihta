## Происхождение входов

Все три сценария взяты из учебного набора Алексея `I4_reference_v1` с тремя заказами и рецептурами H/L. Входы побайтово совпадают с `alexey/iteration4/scenarios_v1.json`. SHA-256 `4d6b9ee09651c418987e40e94c1810365afbe91bdc52f063b59c16e11375b8c2` совпал в конфигурации и журнале.

| Сценарий | Происхождение | Запасы A / B / C, т | Оценки q |
|---|---|---|---|
| base | Базовый синтетический пример из I4-A-01 | 1,00 / 0,90 / 1,10 | Исходные шесть оценок v1 |
| deficit | Копия base со снижением запаса B на 0,10 т | 1,00 / 0,80 / 1,10 | Как в base |
| changed_q | Копия base с изменением одной оценки | 1,00 / 0,90 / 1,10 | q(1,H) снижено с 0,95 до 0,10 |

Внутри каждого сценария runner передаёт обоим методам одни и те же заказы, кандидатов, нормы расхода, запасы и явные оценки q. Цель — максимум суммы произведений массы заказа на оценку выбранной рецептуры. Сравнение методов проводится внутри сценария. Изменение q, запасов, ограничений или правил оценки оформляется отдельной серией.

## Результат проверки

- Для каждого метода и сценария журнал содержит четыре замера. Проверены 24 значения времени, медианы, минимумы и максимумы. План и статус берутся из первого повтора.
- В deficit MILP вернул `infeasible`, а эвристика — `no_solution_found`. Обе цели сохранены как null. Отсутствующие и недопустимые планы исключаются из сравнения значений цели, но соответствующие запуски остаются в знаменателе доли успешных запусков.
- `all_passed` в журнале проверяет ожидаемые статусы и цели MILP. Для оценки эвристики используются её собственные статусы и независимая валидация.

## Условия основной серии

На трёх учебных сценариях результаты по допустимости и цели сопоставимы. Все сохранённые замеры короче 120 с. Для полноценного сравнения времени остаются расхождения с I4-A-03:

1. Лимит 120 с передаётся решателю MILP. Общий таймаут на весь запуск обоих методов отсутствует. Замер вызова метода начинается после загрузки входов.
2. Журнал хранит план и статус только первого повтора. Для остальных сохраняется только время. Флаг превышения бюджета проверяется только у первого повтора.
3. В конфигурации указан один поток, но runner не передаёт этот параметр решателю. В журнале есть ОС и версии Python/SciPy, но нет сведений о процессоре и нагрузке.
