# I4-A-01. Сценарии и общая цель

Основание: I3-A-10_G2.md и протокол третьей итерации. Основной метод — MILP с ресурсными ограничениями; одна отдельная жадная эвристика — контроль. ML и тёплый старт не требуются и не заявляются.

| ID | Версия q | Запасы A/B/C, т | Ожидаемый контроль |
|---|---|---|---|
| base | q_v1_reference | 1.0 / 0.9 / 1.1 | Оптимум 2.50, H/L/L |
| deficit | q_v1_reference | 1.0 / 0.8 / 1.1 | Нет допустимого полного плана |
| changed_q | q_v2_first_H_0.1 | 1.0 / 0.9 / 1.1 | Оптимум 2.35: L/H/L или L/L/H |

Все три сценария синтетические. Три заказа по 1 т, по две рецептуры. Расход на 1 т: H=(0.6,0.3,0.1), L=(0.2,0.3,0.5). q_v1: заказ 1 H/L=0.95/0.70, заказ 2=0.90/0.80, заказ 3=0.85/0.75. В q_v2 изменён только q(1,H)=0.1.

Общая цель внутри каждого сценария: max sum demand_t*q*assignment. Единица — условный балл·т, не тонна годного. Обязательны полное назначение каждой позиции одной разрешённой рецептуре и баланс всех трёх ресурсов. Для обоих методов входы, q, запасы и допустимость одинаковы. Сравнение целей разных q не называется улучшением одной задачи.

Истина контрольного примера — независимый полный перебор восьми вариантов. Малые сценарии проверяют корректность и не доказывают ускорение на больших задачах. Производственный сценарий не включён: доступные запасы и технологические разрешения не подтверждены. Масштабная серия потребует отдельного фиксированного набора до запуска.

Контракт входа: `scenarios_v1.json`; q передаётся явно по ключу order_id+recipe_id. Запрещён молчаливый fallback q=0.5. SHA256 файла: `4d6b9ee09651c418987e40e94c1810365afbe91bdc52f063b59c16e11375b8c2`. Смена файла или q создаёт новую версию набора. Контракт выхода: список order_id/recipe_id, сырой статус, objective, bound, gap и этапы времени; отсутствие поля отмечать null и причиной, не нулём.
