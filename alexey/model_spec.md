# Математическая постановка — I2-A-03

Статус: постановка для проверки Кириллом, производственные параметры не согласованы. Источники: `docs/MILP_Solvers.ipynb` (подготовка данных и MILP), техническая карта I1-K-04, документы и код I2-K-01…06.

## Обозначения и источники

| Символ | Смысл и единица | Источник |
|---|---|---|
| O, o | Множество позиций заказов и одна позиция | Заказы.xls; period + order_id в zakazy.csv |
| R_o, r | Разрешённые рецептуры позиции и одна рецептура | Шихта.xls + правило предприятия; техническая связь по mass_code не доказывает разрешение |
| C, c | Учитываемые компоненты сырья | Шихта.xls, powder_code; соответствие складским материалам требует справочника |
| d_o | Потребность позиции, т смеси в учебной модели | demand_t; база тоннажа и сложение заказа с дополнительным требуют подтверждения |
| a_rc | Расход компонента c на тонну по рецептуре r, т/т | Нормы рецептуры; norm_pct/100 допустимо только при подтверждённой базе |
| A_c | Доступный запас компонента, т | Подтверждённых производственных остатков нет; в учебной модели задаётся отдельно |
| x_or | 1, если для позиции o выбрана r; иначе 0 | Искомое решение, безразмерное |

Идентификатор r уникален внутри расчёта и включает период, марку и номер шихты либо однозначно отображается на этот составной ключ.

## Ограничения

Для каждой позиции выбрать ровно одну разрешённую рецептуру:

$$\sum_{r\in R_o}x_{or}=1,\quad o\in O.$$

Расход каждого компонента не превышает доступный запас:

$$\sum_{o\in O}\sum_{r\in R_o}d_o a_{rc}x_{or}\le A_c,\quad c\in C.$$

$$x_{or}\in\{0,1\}.$$

Если R_o пусто, выполнить все заказы в такой постановке невозможно; позицию нельзя молча удалить. Нельзя пропускать компонент с неизвестным запасом. Нулевой запас является действительным ограничением. При единственной рецептуре у каждого заказа остаётся проверить баланс; содержательного выбора нет.

## Границы и допущения

Один период; неделимые позиции; фиксированные составы; рецептура может использоваться для нескольких заказов. Ограничение «одна рецептура только одному заказу» не вводится. Печи, смены, закупки и изменение состава не моделируются. Предположение об одинаковом a_rc для всех заказов, использующих r, явно относится к этой постановке.

В notebook supply строится как расход × 1.30, нулевые наблюдаемые расходы исключаются; это свойства реализации, а не подтверждённые запасы. Нормы не приводятся к 100% автоматически.

Постановка не зависит от метода решения. MILP, эвристики и полный перебор могут проверяться на одних входах. Цель и контракт определены ниже и в связанных документах.

## Сверка с работой Кирилла

Загрузчик I2-K-01 сохраняет происхождение строк; I2-K-02 отделяет события от итогов; I2-K-03 проверяет связи. В `scripts/i2_k06_milp.py` реализовано ровно одно назначение на заказ, но нет матрицы a_rc, запасов A_c и ограничений сырья. Его результат не является проверкой полной модели выше. Производственные R_o, a_rc и A_c требуют ответов из словаря I1-A-05.

## Цель

$$\max F(x)=\sum_{o\in O}\sum_{r\in R_o}d_o q_{or}x_{or}.$$

q_or — явная оценка разрешённого кандидата. В учебном случае это условные баллы в [0,1], цель — балл·т. Производственный смысл качества не подтверждён.
