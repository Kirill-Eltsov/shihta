# I2-A-03 — Контракт входных данных модели

Контракт задаёт расчётные сущности, а не объявляет готовыми существующие CSV Кирилла. Перед использованием производственных выгрузок необходим явный адаптер и подтверждение смысла полей.

| Таблица | Обязательные поля | Единицы и правила |
|---|---|---|
| orders | order_key, period, mass_code, demand_t | order_key уникален внутри набора; demand_t > 0, конечное число, т смеси в учебном примере |
| candidates | order_key, recipe_key | Уникальные пары разрешённых выборов; минимум одна на заказ; внешний ключ на orders и recipes |
| recipes | recipe_key, period, mass_code, shikhta_num | recipe_key однозначно определяет состав, номера шихты без марки недостаточно |
| usage | recipe_key, resource_key, usage_t_per_t | Конечный неотрицательный расход т/т. Для каждого ресурса состав полный; ноль только явно заданный или обоснованный составом |
| stocks | resource_key, stock_t | Уникальный ключ; конечный stock_t ≥ 0, т. Запас нужен для каждого учитываемого ресурса |
| quality | order_key, recipe_key, q, q_definition | Для каждой пары candidates явное конечное q и единое определение критерия. Для учебного сценария баллы в [0,1] |
| plan (выход) | order_key, recipe_key | Ровно одна строка на каждый заказ, только пары candidates; нет лишних заказов и дубликатов |

Происхождение производных данных сохраняется в src_file, src_sheet, src_row или в отдельном однозначном реестре происхождения. Вместе со сценарием фиксируются версия входов, единицы, определение q, параметры и режим educational/production.

## Входная проверка

Проверить уникальность ключей, внешние ключи, конечность чисел, диапазоны, полное покрытие заказов кандидатами и всех кандидатов оценками. Несогласованные пропуски — ошибка. Итоговые строки исходных XLS не превращать в заказы или события. Дополнительную марку сохранить для проверки разрешений. Сценарий с нулевым или отрицательным спросом требует отдельного явного правила; молча исключать его нельзя.

## Проверка выхода

Сначала полнота и разрешённость назначений, затем сырьевой баланс, затем независимый пересчёт цели с переданным q. Учебный допуск по ресурсу: 1e-8 т + 1e-9 × |stock_t|. Допуск сравнения цели: 1e-6 балл·т. Допуски предприятия отдельно не согласованы. План с отсутствующим назначением не допустим, даже если расход равен нулю.

## Сопоставление с таблицами Кирилла

zakazy.csv даёт period, order_id, mass_code, demand_t; составной order_key нужно определить явно. recepty.csv содержит строки компонентов, а не одну строку на рецепт. Поле norm_pct переводится в usage_t_per_t только после подтверждения базы. kachestvo.csv даёт агрегаты и оценки, но не подтверждает ML-метку и готовность quality для любого кандидата. Таблицы candidates, stocks и quality требуют проверки по контракту, не считаются соответствующими только по названию.

Обработка 36 листов и проверка связи по mass_code в I2-K-01…03 не заменяют проверку разрешений и наличие реальных запасов. Заполнить запасы по движениям без начального остатка нельзя.

## Обоснование выбора постановки

Выбираем готовые фиксированные рецептуры, чтобы отделить задачу назначения от изменения химического состава. Бинарное решение отражает выполнение всей позиции одним вариантом. Общие запасы связывают решения по разным заказам и создают содержательный выбор. Расход и q задаются раздельно, чтобы проверять допустимость независимо от критерия.

Неизвестны: производственные разрешения и дополнительная марка, база тоннажа и норм, потери, начальные доступные остатки, справочник сырья и интерпретация качества. Для учебного примера эти параметры задаются явно; внешнее согласование не заявлено.
